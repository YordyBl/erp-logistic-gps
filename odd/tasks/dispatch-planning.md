# Feature: Web dispatch planning and route progress
Objective: Expose existing manual route planning, assignment, reassignment, redispatch, and progress workflows in the dispatcher web workspace.
Branch: feature/phase-4-delivery-execution; local-only, no commit, push, or PR; strategy: ask-on-risk; runner: Vitest, TypeScript, ESLint, isolated PostgreSQL.
Engram mirror: synchronized under project `erp-logistic-gps`, topic `odd/dispatch-planning/tasks`.

## Specs

- S1: Plan checklist, verbatim: «Planificar desde la web rutas manuales con varias paradas y varios pedidos por parada.» Provide a dispatcher web flow that uses the existing route-planning contract to create a route with ordered stops and one or more orders per stop. Acceptance: route creation and validation happen through the application API; no direct/manual API calls are required.
- S2: Plan checklist, verbatim: «Asignar conductor y vehículo; reasignar recursos y redespachar pedidos conforme a las reglas de negocio.» Use the existing ADMIN/DISPATCHER route assignment and reassignment rules. User confirmed redispatch clarification verbatim: «claro pero el historial mostraría que tuvo una incidencia cierto?» A returned order may be planned on a new route, its previous route association remains historical, and the dispatcher view must make the incident/returned history visible before redispatch; do not fabricate incident details absent from persisted records.
- S3: Plan checklist, verbatim: «Consultar desde la web el estado y progreso de rutas y pedidos.» Show tenant-scoped route and order states/progress in the dispatcher workspace, distinguishing planned, in-progress, completed, and returned-order outcomes using existing persisted status and incident history.
- S4: Plan checklist, verbatim: «Completar sin llamadas manuales a la API el flujo desde la creación o importación del pedido hasta su asignación a una ruta.» Connect existing order creation/import and route planning screens so an operator can select eligible orders, create/assign a route, and confirm the result through the UI.
- S5: Preserve existing route and order contracts, tenant boundaries, transactional persistence, active driver/vehicle restrictions, and DRIVER-only assigned-route execution. Do not add map, ETA, GPS, or public tracking; those are later plan sections. No remote operations or dependency audit are authorized by this feature request.
